# Свой VPN на WireGuard: удалённый доступ к сети

Инструкция для случая, когда нужно попасть из интернета в закрытую сеть: к серверам, панелям управления, оборудованию. Наружу открывается один UDP-порт, всё остальное остаётся закрытым.

Адреса ниже — примеры, подставьте свои.

| Что | В примере |
|---|---|
| Внутренняя сеть | `192.168.10.0/24` |
| Роутер | `192.168.10.1` |
| VPN-сервер | `192.168.10.5` |
| Сервер, к которому нужен доступ | `192.168.10.20` |
| Панель виртуализации или другой хост | `192.168.10.21` |
| Внешний адрес роутера | `203.0.113.10` |
| Сеть туннеля | `10.77.0.0/24` |
| Сетевой интерфейс сервера | `ens18` |

## Как это устроено

```
Телефон, ноутбук → интернет → роутер (проброс UDP 51820) → VPN-сервер → внутренние серверы
```

- **Клиент** шифрует трафик и отправляет его на внешний адрес роутера.
- **Роутер** передаёт этот UDP-порт на VPN-сервер.
- **VPN-сервер** расшифровывает трафик и пересылает его во внутреннюю сеть.
- **NAT** на VPN-сервере подменяет адрес клиента своим. Внутренние серверы отвечают VPN-серверу и настраивать их не нужно.

У каждой стороны пара ключей. Закрытый ключ не покидает устройство, открытым можно делиться свободно. Сервер отвечает только тем, чей открытый ключ у него записан, на остальные пакеты он молчит, и порт снаружи выглядит закрытым.

## Что проверить заранее

**Внешний адрес принадлежит роутеру.** Выполните на компьютере внутри сети:

```
curl -4 -s https://ifconfig.me
```

Сравните ответ с адресом WAN в настройках роутера. Если они разные, особенно если на WAN адрес вида `10.x`, `192.168.x`, `172.16–31.x` или `100.64–127.x`, значит, провайдер использует общий адрес, и проброс порта работать не будет. Тогда нужен внешний адрес у провайдера или сервер-посредник с белым адресом.

**Адрес постоянный.** Если он меняется, понадобится динамический DNS: в `Endpoint` клиента пишется имя, а не адрес.

**Подсети не пересекаются.** Сеть туннеля не должна совпадать ни с внутренней сетью, ни с другими вашими сетями.

**Свободный адрес для сервера.** Он должен быть вне диапазона DHCP роутера, иначе роутер однажды выдаст его другому устройству. Проверка, что адрес не занят:

```
ping -c 3 -W 1 192.168.10.5
ip neigh show 192.168.10.5
```

`INCOMPLETE` или пустой вывод значит, что адрес свободен.

## Где разместить сервер

Лучше всего подойдёт отдельная маленькая виртуальная машина или отдельный компьютер: 1 процессор, 512 МБ–1 ГБ памяти, 8 ГБ диска. Не ставьте VPN на сервер, ради которого он нужен: доступ понадобится как раз тогда, когда этот сервер сломан. Контейнер LXC тоже возможен, но ВМ со своим ядром проще и независимее.

Включите автозапуск ВМ вместе с хостом.

Инструкция написана для Debian 13. При установке:

- язык English и раскладка American English: так меньше ошибок при вводе паролей;
- пароль root оставьте пустым: вход под root отключится, а ваш пользователь получит `sudo`;
- из программ оставьте только SSH server и standard system utilities.

Веб-консоль гипервизора часто искажает спецсимволы и не даёт вставлять текст. Как только сервер получит адрес, работайте по SSH.

## Постоянный адрес

Посмотрите имя интерфейса и файл настроек:

```
ip -br -4 addr
cat /etc/network/interfaces
```

Замените настройку интерфейса в `/etc/network/interfaces`:

```
auto ens18
iface ens18 inet static
    address 192.168.10.5/24
    gateway 192.168.10.1
```

Используйте `auto`, а не `allow-hotplug`: так интерфейс точно поднимется при загрузке.

Без DHCP пропадёт и настройка DNS, поэтому укажите его вручную:

```
echo 'nameserver 192.168.10.1' | sudo tee /etc/resolv.conf
```

Перезагрузите сервер и проверьте:

```
sudo reboot
ip -br -4 addr
ip route show default
getent hosts debian.org
```

## Установка

```
sudo apt update
sudo apt full-upgrade
sudo apt install wireguard-tools nftables unattended-upgrades
```

Сервер будет смотреть в интернет, поэтому обновления безопасности должны ставиться сами. Установка пакета этого не включает. Создайте `/etc/apt/apt.conf.d/20auto-upgrades`:

```
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Unattended-Upgrade "1";
```

Проверка:

```
apt-config dump APT::Periodic::Unattended-Upgrade
```

## Ключи сервера

```
sudo -i
umask 077
wg genkey > /etc/wireguard/server.key
wg pubkey < /etc/wireguard/server.key > /etc/wireguard/server.pub
cat /etc/wireguard/server.pub
exit
```

- `umask 077` делает новые файлы доступными только root.
- `wg genkey` создаёт закрытый ключ.
- `wg pubkey` получает из него открытый.

Выводится только открытый ключ. Закрытый никому не показывайте.

## Настройка туннеля

`/etc/wireguard/wg0.conf`:

```
[Interface]
Address = 10.77.0.1/24
ListenPort = 51820
MTU = 1280
PostUp = wg set %i private-key /etc/wireguard/server.key
```

| Строка | Зачем |
|---|---|
| `Address` | адрес сервера внутри туннеля |
| `ListenPort` | порт, на который подключаются клиенты |
| `MTU` | наибольший размер пакета в туннеле |
| `PostUp` | читает закрытый ключ из файла, поэтому в настройках его нет |

**Про MTU.** Обычно WireGuard работает с 1420. На линиях, где большие пакеты теряются, туннель выглядит так: `ping` работает, а страницы и SSH зависают. Значение 1280 надёжно и для удалённого управления не заметно по скорости. Если нужна скорость, попробуйте поднять его позже.

## Фильтр

`/etc/nftables.conf`:

```
#!/usr/sbin/nft -f
flush ruleset

table inet filter {
    chain input {
        type filter hook input priority filter; policy drop;
        ct state established,related accept
        iif lo accept
        icmp type echo-request accept
        udp dport 51820 accept
        tcp dport 22 ip saddr { 192.168.10.0/24, 10.77.0.0/24 } accept
    }

    chain forward {
        type filter hook forward priority filter; policy drop;
        tcp flags syn tcp option maxseg size set rt mtu
        ct state established,related accept
        iifname "wg0" oifname "ens18" ip daddr { 192.168.10.20, 192.168.10.21 } accept
    }
}

table ip nat {
    chain postrouting {
        type nat hook postrouting priority srcnat; policy accept;
        ip saddr 10.77.0.0/24 oifname "ens18" masquerade
    }
}
```

Пакеты проверяются в трёх местах:

- `input`: пакеты к самому серверу;
- `forward`: пакеты через сервер во внутреннюю сеть;
- `postrouting`: подмена адреса.

`policy drop` значит «запрещено всё, что не разрешено явно».

| Правило | Зачем |
|---|---|
| `ct state established,related accept` | пропускать ответы на разрешённые соединения |
| `iif lo accept` | разрешить серверу обращаться к самому себе |
| `udp dport 51820 accept` | порт WireGuard |
| `tcp dport 22 ip saddr {...}` | SSH только изнутри и из туннеля |
| `tcp flags syn ... rt mtu` | подгонять размер TCP-пакетов под MTU |
| `ip daddr {...}` | куда можно попасть из туннеля |
| `masquerade` | подмена адреса клиента |

Если нужна вся внутренняя сеть, а не отдельные адреса, уберите `ip daddr { ... }`. Отдельные адреса безопаснее: украденное устройство откроет только их.

Проверка файла без применения:

```
sudo nft -c -f /etc/nftables.conf
```

## Запуск

Разрешите пересылку пакетов и включите службы:

```
echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/99-vpn.conf
sudo sysctl -p /etc/sysctl.d/99-vpn.conf
sudo systemctl enable --now nftables
sudo systemctl enable --now wg-quick@wg0
sudo wg show
```

`enable --now` запускает службу и включает её автозапуск. Состояние `active (exited)` у `wg-quick` нормально: туннель работает в ядре, а служба только запускает его.

## Проброс порта на роутере

| Поле | Значение |
|---|---|
| Внешний порт | `51820` |
| Внутренний адрес | `192.168.10.5` |
| Внутренний порт | `51820` |
| Протокол | **UDP** |

Только UDP и только этот порт. SSH и веб-панели наружу не открывайте.

## Подключение устройства

У каждого устройства свой ключ и свой адрес: потерянный телефон можно отключить, не трогая остальные.

В приложении WireGuard создайте пустой туннель, ключи оно сделает само:

```
[Interface]
PrivateKey = создаётся приложением
Address = 10.77.0.2/32
MTU = 1280

[Peer]
PublicKey = ОТКРЫТЫЙ_КЛЮЧ_СЕРВЕРА
AllowedIPs = 10.77.0.1/32, 192.168.10.20/32, 192.168.10.21/32
Endpoint = 203.0.113.10:51820
PersistentKeepalive = 25
```

| Строка | Зачем |
|---|---|
| `Address` | адрес устройства в туннеле, у каждого свой |
| `AllowedIPs` | что отправлять в туннель |
| `Endpoint` | куда подключаться |
| `PersistentKeepalive` | короткий пакет раз в 25 секунд, чтобы роутер клиента не закрывал соединение |

С таким `AllowedIPs` в туннель идут только указанные адреса, остальной интернет работает как обычно. Перечисление отдельных адресов (`/32`), а не всей сети, защищает от конфликта, если домашняя сеть клиента использует те же адреса. Адрес `10.77.0.1` даёт доступ по SSH к самому VPN-серверу.

Чтобы пустить весь трафик через VPN, укажите `AllowedIPs = 0.0.0.0/0`, добавьте `DNS = 192.168.10.1` и разрешите на сервере выход в интернет из туннеля.

Затем допишите устройство в конец `/etc/wireguard/wg0.conf` на сервере:

```
[Peer]
# Ноутбук
PublicKey = ОТКРЫТЫЙ_КЛЮЧ_УСТРОЙСТВА
AllowedIPs = 10.77.0.2/32
```

На сервере `AllowedIPs` значит другое: какой адрес разрешён этому ключу. Здесь всегда один адрес устройства.

Применение и проверка:

```
sudo systemctl restart wg-quick@wg0
sudo wg show
```

## Проверка

Проверяйте из другой сети, например через раздачу с телефона, иначе проброс порта не проверяется.

```
ping -c 3 10.77.0.1
ping -c 3 192.168.10.20
ssh пользователь@192.168.10.20
```

Откройте веб-панель целиком: только так видно проблемы с размером пакетов. Затем перезагрузите VPN-сервер и убедитесь, что туннель поднялся сам.

## Обслуживание

**Отключить устройство.** Удалите его раздел `[Peer]` и перезапустите `wg-quick@wg0`.

**Добавить внутренний адрес.** Допишите его в `ip daddr { ... }`, проверьте файл и выполните `sudo systemctl restart nftables`. На устройствах добавьте адрес в `AllowedIPs`.

**Ключи SSH с ноутбука:**

```
ssh-keygen -t ed25519
ssh-copy-id пользователь@10.77.0.1
```

Вход по паролю можно оставить, если SSH доступен только изнутри и из туннеля, а пароль надёжный.

## Если не работает

Сначала выполните `sudo wg show` на сервере.

| Что видно | Где искать |
|---|---|
| У устройства нет `latest handshake` и `endpoint` | адрес в `Endpoint`, ключи, проброс порта, сеть устройства |
| Переключатель в приложении включён, а `latest handshake` нет | включённый переключатель не значит, что соединение установлено |
| Рукопожатие есть, внутренний адрес не открывается | `AllowedIPs` на устройстве, `ip daddr` в фильтре |
| `ping` проходит, страницы и SSH зависают | уменьшите MTU |
| Работает по Wi-Fi, не работает через мобильный интернет | оператор может блокировать WireGuard |
| Туннель не запускается | `sudo systemctl status wg-quick@wg0` |

**Частые ошибки:**

- опечатка в порту или пути к файлу. Проверить: `sudo grep -E 'ListenPort|PostUp' /etc/wireguard/wg0.conf`;
- на устройстве в `Peer` указан свой ключ вместо ключа сервера;
- опечатка в `AllowedIPs` на устройстве. Трафик не попадает в туннель, поэтому соединения нет совсем, и выглядит это как ошибка сети;
- на телефоне работает другой VPN: на iPhone одновременно активен только один;
- `AllowedIPs` проверен по обрезанному снимку экрана: смотрите значение целиком.

## Безопасность

- Закрытые ключи никогда не передавайте и не храните в репозиториях.
- Открывайте наружу только UDP-порт WireGuard.
- Выдавайте доступ к отдельным адресам, а не ко всей сети.
- Оставьте запасной путь в сеть: VPN зависит от хоста, роутера и интернета площадки и при их сбое недоступен.
